# Android host and cross-target builder parity

The Android release target is the guest-visible behavior available on iOS and macOS. Existing Apple limitations are part of the reference. Record the Apple revision and observed result for each comparison. When Apple implements a feature using a platform-specific API, specify the observable result and the target device capabilities required to reproduce it.

Work in two tracks. In the host, keep Horizon semantics shared and port the underlying OS operations. In graphics, run the same synthetic inputs through NVN on Metal and NVN on Vulkan. Each draft PR adds a capability and verifies observable output. Run games against fixed scenes for integration, timing and regression measurements. The [NVN command and resource matrix](nvn-vulkan-parity.md) defines the graphics work independently of any title.

**Current evidence.** In `.github/workflows/tests.yml`, NDK API 30 + static bionic under QEMU runs the gate fixture and big-stack calls. `dm/host/tests/gate/{fixture.py,roundtrip.c,reject_foreign.py}` generates linked synthetic modules, resolves a cross-module call, a registered test service and a production SDK steady-clock import, reads a rewritten guest counter, executes a callback and SVC return on two pthreads, checks TLS, host x18 and trap state, and rejects incompatible rewrites. The fixture supplies its own SVC handler. Static bionic memory and signal binaries run on an ARM64 Ubuntu kernel. `t_svc_memory.c` exercises the production memory dispatcher, heap/alias/stack ownership, limits, guards and concurrency. `t_fault_access.c` checks the actual read/write fault and resumption on an existing alternate stack. The Linux Mesa job verifies a clear and full/compact textured draws through fences and pixel readback. The same replay ran locally on an ARM64 Android 15 emulator with llvmpipe, including fenced readback of two layers and their row padding. The NDK public NVN fixture links the full registry and production ARM64 thunks. It checks bootstrap and device lookup, records through the guest API and verifies a fenced Vulkan readback on Android. The shutdown fixture invokes the production termination handler on Android. It verifies the order of recorder, cheat, audio and graphics cleanup, duplicate requests, and the watchdog deadline when a graphics drain stalls. The production Android filesystem and save-sync suites exercise rollback after a short write, symlinks, concurrent commits, remount and bundle metadata, with static and dynamic bionic binaries. App storage selection, full app and APK lifecycle tests are still open.

**Donor evidence.** `32b0ef2c:dm/android/README.md` reports Hollow Knight 1.5.12620 at about 59 fps in Dirtmouth on the Android 13 ANBERNIC RG Slide (Unisoc T820, Mali-G57), with sound, saves, controls and a menu. Its NDK Makefile, CLI, NativeActivity and APK tooling are available for porting. Only that hardware is claimed tested. Its AAC path was silent and several driver/scheduler shims explicitly returned failure. The current shared host has newer services and behavior.

## Target qualification

1. Define the target manifest and isolate shared preparation behind existing Apple entry points.
2. Land full NDK headless link/bootstrap and explicit capability gaps, with the same synthetic guest and service conformance on Apple and Android.
3. Qualify thread/memory, FS/save/clock behavior, lifecycle, input and media adapters.
4. Build and launch a synthetic APK on hardware, exercising first import, update, suspension and persistence. Develop GPU conformance in parallel, with separate gates for NVN, guest Vulkan and desktop GL.
5. Release each target only at its demonstrated coverage. Use named games as comparative workloads for frame correctness, frame-time percentiles, cold/warm pipeline stalls, memory and stability.
6. Bring up ARM64 Linux against the same suite. Gate Steam Deck separately on translated execution.

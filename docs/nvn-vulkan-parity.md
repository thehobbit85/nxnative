# NVN replay parity with the Apple renderer

The contract is the observable behavior of the public NVN calls on the Mac and iOS. A record may cover multiple entry points and payload forms. Games supply comparative benchmarks and integration smoke tests. The cases below use synthetic inputs. See the [host and builder plan](android-parity.md) for end-to-end qualification.

**Compared revisions.** The active branch is `codex/cross-platform-runtime`, rebased onto Apple upstream `777a5f6c618a38cd2d7f795f465466fb56920534`, with Android integration at `b96b887f`. The original inventory used Vulkan `4a93a069074bfc4da3fa7394af82dd6fa8db4eac` and Apple `de23ae82ad35453417ed4eda942d27d07e5d74df`; the source line references below remain historical locators from that inventory. Current conformance claims are the evidence text, not those old line numbers. Upstream additions, including shared sparse physical tiles, are parity obligations. The [execution plan](superpowers/plans/2026-11-04-vulkan-parity.md) tracks the resumed work on the existing branch.

**Source map.** R is `dm/gfx/nvn/hle_nvn.c` (command writer at 829–1166, 2360–2369, 2532–2584 and 2689–2738). H is `dm/gfx/nvn/nvn_obj.h` (enum and payloads, 100–195). M is `dm/gfx/nvn/nvn_mtl.m` (main execution switch 11143–11276, state 7843–7905, draw 9830–10250 and transfer/compute 10251–10939). V is `dm/gfx/nvn/vulkan/nvn_vk.c` at the committed revision (dispatch switch 1662–1722). F is the committed `dm/gfx/nvn/vulkan/tests/t_replay.c` (synthetic lists, 18–123). References in the table identify the consuming code as well as the record.

**Evidence.** “Fixture-proven slice” means a checked outcome in F depends on this narrow path in the committed, driver-backed test suite. The full and compact draws and the pitched two-layer readback passed on ARM64 Android 15 with llvmpipe. “Partial” means a known missing or divergent behavior, even when F exercises a subset. “Handler unverified” means a plausible consumer exists but F supplies no distinguishing oracle. “Missing” means the committed replay cannot deliver the stated reference feature. After rebasing onto upstream main at `1d4b8e82`, the 43 explicit Vulkan cases and 12 default cases account for 55 active records. Upstream added `OP_MULTI_DRAW` for large indirect draw lists; its Vulkan implementation remains open. `OP_BEGIN` is obsolete and `OP_COUNT_` is the sentinel.

**Transfer conformance.** The public NVN fixture allocates a guest memory pool, creates the texture and view, records layered clears and a pitched subregion copy, submits the resulting bytes, then waits through public FenceSync/SyncWait. It verifies every destination byte including the guard regions and row/image padding. The same fixture runs on Metal and Vulkan. On Apple Silicon with a Vulkan SDK and driver installed, run `make -C dm/gfx/nvn/vulkan GAME=<profile-id> recorded-transfer-conformance`. Use a profile from the repository. The NDK `android-recorder` target builds the same public fixture for ARM64 Android. Run `t_recorded_transfer_android` on a device with Vulkan. No game data is needed. Compressed synthetic capture files also round-trip in both directions between Apple libcompression and the reference LZFSE implementation on Android. The other synthetic draw and compute cases currently submit records directly. Independent same-list GPU-consumer and 3D transfer cases are still needed.

## Work outside the command stream

- **Texture and sampler objects.** Audit all format/usage/dimension/view combinations, reinterpretation, typed/buffer textures, swizzle, compare/border/aniso, BC/ASTC upload and round-trip, sparse mapped/unmapped pages, aliasing by guest memory, storage ownership, pool mutation and destroy/reuse with in-flight work. V:400–477, 561–758 implement subsets. V:2022 returns zeros for public CPU texture reads. Exercise public WriteTexels/ReadTexels and alternate registrations over identical memory, with canaries and an outstanding fence.
- **Shaders and resources.** Public program creation, shader key/variant lookup, code and reflection export, resource dimension/type/arrays, separate sampler/image/texel buffers, GPU addresses in CBUFs, geometry and transform feedback translation, geometry hazards, driver constants, binding and specialization all participate. F compiles hand-written GLSL and handmade reflection, so its pass excludes the actual translator. Exercise generated microshaders through the pack/export/load paths. V:915–977,1267–1332. Track Apple unsupported cases separately from parity obligations.
- **Queue, process and window.** No opcode covers CPU polling, queue/per-command sync APIs, acquire/present, crop/scale, front-end surface resize/recreation, save/resume, timeouts and native queue submission failures. V:1628ff,1778–1976 includes present and placeholder hooks. Check frames and fences through native entry points. Compare software Vulkan for semantics and ARM Vulkan hardware for WSI, memory limits, timing, thermal behavior and supported feature fallbacks.
- **Other graphics APIs and platform services.** The NVN-to-Vulkan translator cannot exercise Switch titles' guest Vulkan or desktop OpenGL entry points (`dm/gfx/vk/hle_vk.m`, `dm/gfx/gl/hle_gl.m`). Inventory those frontends separately, then host SVC/IPC/memory/signals/TLS, file/save, input/controller/sensors, audio/video, app lifecycle, pack/build/launch, diagnostics and parity across destination platforms. This table is specifically the NVN recorder slice.
- **Performance.** Separate correctness oracles from throughput, frame pacing, frame-time tails, memory, CPU/GPU wait, uploads/caches, shader cold/warm startup and power. Collect repeatable scenes and resource curves with explicit baselines and tolerances. Track placeholder metrics separately from measured zeros.

## Review order

1. Real recorder fixture ABI and transfer readback through public APIs. The corrected layout and pitched array case are in #10. Wire in the public recorder and cover GPU-before-fence consumers, 3D targets and region/capability negatives.
2. GPU/CPU buffer ownership and coherent ordered copies/clears/updates, compute and graphics SSBO writes, fences and direct buffer/texture read APIs.
3. Descriptor and image semantics: land the storage-image increment on the repaired harness; typed/buffer/array/separate descriptors, pools, deferred binds, filter/compare and aliases in independently reviewable increments.
4. Image formats, typed views, subresource copies, resolves and draw-texture; MRT/depth-stencil/masked clears and per-attachment MSAA state.
5. Raster and pipeline state: depth range/clamp, swizzle/origin, bias, blending/logic/alpha, raster discard, instancing/divisors, compact/full inputs and push constants.
6. Primitive execution: faithful first/index/base IDs, restart, direct/indirect/counted draws and dispatch; geometry expansion and transform feedback (capture/control/consumer).
7. Ordering and queries: shader hazards, real samples-passed, ordered GPU timestamp pairs, render predicates, negative tests and sync integration.
8. Temporal upscaling, presentation/device lifecycle, guest Vulkan and OpenGL, packer/host/platform tracks and comparative end-to-end benchmarking, each with its own acceptance tests and PRs.
